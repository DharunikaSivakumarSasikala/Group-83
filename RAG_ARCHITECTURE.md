# SkillScope AI RAG Architecture

## Implemented RAG boundary

1. The employee answer, assessment question and required concepts form the retrieval query.
2. Role filtering restricts the search to the employee's technical domain.
3. TF-IDF and cosine similarity retrieve the top five evidence chunks.
4. The prompt builder adds the question, untrusted employee answer, rubric and retrieved evidence.
5. Ollama generates a structured evaluation using only the supplied evidence.
6. The validator clamps the score and rejects citations that are not in the retrieved set.
7. The output contains strengths, missing concepts, improvement areas, learning activities, confidence and evidence IDs.
8. Every output is marked for human review.

## Safety behaviour

- Employee text is explicitly treated as untrusted content.
- The model is instructed not to follow instructions inside an employee answer.
- Temperature is set to zero for more stable output.
- Generated evidence IDs must belong to the retrieved evidence.
- An invalid score, invalid JSON or unsupported citation fails validation.
- When Ollama is offline, the system reports retrieval-only fallback mode and does not claim that RAG ran.

## Current limitation

The generator integration is implemented and tested with a mock generator. A live
Ollama response must be tested on a machine where Ollama and the configured model
are installed. Dense embeddings and hybrid retrieval remain the next retrieval
improvement.

## Version 3 marking and feedback boundary

The final assessment percentage is deterministic rather than generated by the language model. Written questions use required-concept coverage after simple word normalisation; quizzes use the fixed correct option; skipped questions receive zero. Eighty percent is the competency threshold and the overall result is the mean of all ten question accuracies.

RAG is applied to weak written responses to generate developmental explanations and learning activities. Expected answers and learning URLs remain grounded in curated dataset fields. This separation prevents a fluent but unsupported model response from silently changing the employee's score.

## Hallucination evaluation

Hallucination cannot be claimed to be zero merely because citations are present. The team will use human-labelled cases to measure citation precision, citation recall, claim groundedness, unsupported-claim or hallucination rate, score mean absolute error and competency agreement. Retrieval Hit@k and MRR are measured separately because correct generation depends on retrieving the right evidence first.
